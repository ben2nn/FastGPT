# 知识库与工作流导入导出功能设计文档

## 1. 概述

### 1.1 目标

实现基于 parentId 的知识库和工作流完整导入导出功能：

**知识库导入导出**：
- 根据 parentId 递归导出该文件夹下的所有知识库（包括子文件夹）
- 从 JSON 文件导入知识库，支持保留原 ID 或生成新 ID
- 导入时可指定目标父文件夹或导入到根目录

**工作流导入导出**：
- 根据 parentId 递归导出该文件夹下的所有工作流（包括子文件夹）
- 从 JSON 文件导入工作流，保留原 ID
- 导入时可指定目标父文件夹或导入到根目录

### 1.2 技术栈

- 框架：Next.js 14 (Pages Router)
- 数据库：MongoDB (Mongoose)
- 位置：`projects/admin/src/pages/api/extend/`
  - 知识库：`projects/admin/src/pages/api/extend/dataset/`
  - 工作流：`projects/admin/src/pages/api/extend/app/`

## 4. API 设计

### 4.1 知识库导出 API

```
POST /api/extend/dataset/exportByParentId
```

**请求参数**：
```typescript
{
  parentId: string;  // 数据集或文件夹的 ID
}
```

**响应**：JSON 文件下载（Content-Type: application/json）

**JSON 结构**：
```json
{
  "version": "1.0",
  "type": "dataset",
  "exportTime": "2026-05-21T10:00:00Z",
  "teamId": "原始团队ID",
  "datasets": [...],
  "collections": [...],
  "datas": [...],
  "dataTexts": [...],
  "collectionTags": [...]
}
```

**核心逻辑**：
1. 验证 parentId 合法性（ObjectId 格式）
2. 调用 `findDatasetAndAllChildren(parentId)` 获取所有子数据集 ID 列表
3. 并行查询 5 个集合：
   - `datasets`: `{ _id: { $in: datasetIds } }`
   - `dataset_collections`: `{ datasetId: { $in: datasetIds } }`
   - `dataset_datas`: `{ datasetId: { $in: datasetIds } }`
   - `dataset_data_texts`: `{ datasetId: { $in: datasetIds } }`
   - `dataset_collection_tags`: `{ datasetId: { $in: datasetIds } }`
4. 排除已软删除的文档（`deleteTime: { $ne: null }`）
5. 组装 JSON 结构并返回文件流下载

### 4.2 知识库导入 API

```
POST /api/extend/dataset/importFromJson
Content-Type: multipart/form-data
```

**请求参数**：
```typescript
{
  file: File;                    // JSON 文件
  keepOriginalId: boolean;       // 是否保留原 ID
  targetParentId?: string;       // 目标父文件夹 ID（可选，默认根目录）
}
```

**响应**：
```typescript
{
  success: boolean;
  data: {
    datasetsCount: number;       // 导入的数据集数量
    collectionsCount: number;    // 导入的集合数量
    datasCount: number;          // 导入的数据条数
    dataTextsCount: number;      // 导入的全文索引数
    collectionTagsCount: number; // 导入的标签数
  }
}
```

**核心逻辑**：
1. 解析上传的 JSON 文件，验证格式和 version 字段
2. 如果 `keepOriginalId = false`：
   a. 为所有文档生成新的 ObjectId
   b. 建立 ID 映射表：`oldId -> newId`
   c. 更新所有文档中的引用字段
3. 如果 `targetParentId` 存在：
   a. 更新顶级 datasets 的 `parentId` 为 `targetParentId`
4. 设置 `teamId`、`tmbId` 为当前管理员身份
5. 批量写入 5 个集合（按依赖顺序）
6. 返回导入结果统计

### 4.3 工作流导出 API

```
POST /api/extend/app/exportByParentId
```

**请求参数**：
```typescript
{
  parentId: string;  // 应用或文件夹的 ID
}
```

**响应**：JSON 文件下载（Content-Type: application/json）

**JSON 结构**：
```json
{
  "version": "1.0",
  "type": "app",
  "exportTime": "2026-05-21T10:00:00Z",
  "teamId": "原始团队ID",
  "apps": [...],
  "versions": [...]
}
```

**核心逻辑**：
1. 验证 parentId 合法性（ObjectId 格式）
2. 递归查找所有子应用：
   - 查询 `apps` 集合中 `parentId` 匹配的文档
   - 递归查找子应用的子应用
3. 并行查询 2 个集合：
   - `apps`: `{ _id: { $in: appIds } }`
   - `app_versions`: `{ appId: { $in: appIds } }`
4. 排除已软删除的文档（`deleteTime: { $ne: null }`）
5. 组装 JSON 结构并返回文件流下载

### 4.4 工作流导入 API

```
POST /api/extend/app/importFromJson
Content-Type: multipart/form-data
```

**请求参数**：
```typescript
{
  file: File;                    // JSON 文件
  targetParentId?: string;       // 目标父文件夹 ID（可选，默认根目录）
}
```

**响应**：
```typescript
{
  success: boolean;
  data: {
    appsCount: number;           // 导入的应用数量
    versionsCount: number;       // 导入的版本数量
  }
}
```

**核心逻辑**：
1. 解析上传的 JSON 文件，验证格式和 version 字段
2. 保留原 ID，检查是否有 ID 冲突
3. 如果 `targetParentId` 存在：
   a. 更新顶级 apps 的 `parentId` 为 `targetParentId`
4. 设置 `teamId`、`tmbId` 为当前管理员身份
5. 批量写入 2 个集合（按依赖顺序：apps -> versions）
6. 返回导入结果统计

## 5. ID 映射关系

### 5.1 知识库 ID 映射

当 `keepOriginalId=false` 时，需要更新的引用字段：

| 集合 | 需要映射的字段 |
|------|---------------|
| `datasets` | `_id`, `parentId` |
| `dataset_collections` | `_id`, `datasetId`, `parentId` |
| `dataset_datas` | `_id`, `datasetId`, `collectionId` |
| `dataset_data_texts` | `datasetId`, `collectionId` |
| `dataset_collection_tags` | `datasetId`, `collectionId` |

### 5.2 工作流 ID 映射

工作流导入只支持保留原 ID，无需 ID 映射。

## 6. 错误处理

| 错误类型 | HTTP 状态码 | 说明 |
|----------|------------|------|
| JSON 格式校验失败 | 400 | 文件格式不正确 |
| parentId 无效 | 400 | ObjectId 格式不合法 |
| 数据库写入失败 | 500 | 返回错误详情 |
| 重复 ID 冲突 | 409 | 目标数据库已存在相同 ID |
