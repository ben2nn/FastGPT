# 上线说明 — 对外统计接口与 API Key 体系（2026-11-23）

> 变更范围：OpenSpec 变更 `admin-stats-external-api`（分支 `v4.14.6-mod`）
> 关联文档：`openspec/changes/admin-stats-external-api/`（proposal / specs / design / tasks）
> 三方对接文档：`projects/admin/docs/external-statistics-api.md`

## ⚠️ BREAKING 变更（影响内部统计 API 调用方）

| # | 变更 | 影响 | 迁移说明 |
|---|---|---|---|
| 1 | `/api/statistics/list`、`/api/statistics/by-model` 等内部统计接口的 `modelName` 筛选由**精确匹配**（`=`）变为**模糊匹配**（`ILIKE '%x%'`，不区分大小写） | 同名前缀的模型会被一起命中。例：原查 `gpt-4o` 只返回 gpt-4o，现在会同时返回 `gpt-4o-mini`、`GPT-4o-turbo` 等 | 若需精确行为，输入完整模型名称（完整名是自身的模糊子集，结果不变）；仅当存在「名称互为包含」的模型时结果变宽 |
| 2 | `/api/statistics/list` 响应的 `list[]` **新增 `modelId` 字段**（必填） | 新增字段，向后兼容；若有调用方按字段白名单解析需确认兼容 | 无需迁移；`total` 口径因 GROUP BY 增加 `model_id` 可能微增（`model_id` 与 `model_name` 一一对应时无差异） |
| 3 | `/api/statistics/list` 等接口的查询参数类型新增可选 `modelId`、`appName`（TS 类型层面补齐，行为上 validation 早已支持） | 无行为影响 | — |
| 4 | 分页类参数错误（`pageSize` > 100、`pageNum` < 1）的错误码从 `INVALID_TIME_RANGE` 修正为 `INVALID_PAGINATION`（HTTP 仍 400） | 按错误码分支处理分页错误的调用方需同步 | 语义修正：此前这类错误被笼统归入时间错误码 |

## 新增能力

1. **API Key 体系**：`api_keys` 表（幂等建表）、`/api/external/keys/*` 管理接口、后台「API 密钥」页面；Key 仅存 SHA-256 哈希，明文创建时一次性返回
2. **对外统计接口**：`GET /api/external/statistics/list`，Bearer 认证，查询条件支持 appId / appName（模糊）/ modelId / modelName（模糊）/ 时间区间 / 分页
3. **新增索引**：`idx_model_id`（`model_call_logs.model_id`）、`idx_api_keys_enabled`（`api_keys.enabled`）

## 部署步骤

1. 部署新版本 admin 应用
2. 执行数据库初始化（幂等）：`POST /api/system/init`（带 `INIT_TOKEN`）或启动脚本自动执行 schema.sql，确认 `api_keys` 表与两个新索引已创建
3. 管理员登录后台 →「API 密钥」→ 创建第一个 Key → 交付三方并同步对接文档
4. 验证三方拉取（见对接文档 curl 示例）

## 回滚策略

- 代码回滚即恢复原状（`api_keys` 表残留无害，无数据依赖；`idx_model_id` 索引无害）
- 紧急止血（不回滚代码）：在后台禁用全部 Key，对外访问立即关闭
- 内部 BREAKING（modelName 模糊化）随代码回滚一并恢复
