# 模型配置与渠道导入导出功能设计文档

## 1. 概述

### 1.1 目标

实现模型配置和模型渠道的导入导出功能：

**模型配置导入导出**：
- 按模型提供商（provider）和模型类型（type）筛选导出模型配置
- 从 JSON 文件导入模型配置，覆盖模式（存在则更新，不存在则插入）

**模型渠道导入导出**：
- 导出所有渠道配置（通过 AI Proxy API）
- 从 JSON 文件导入渠道配置，覆盖模式（按渠道名称匹配）

### 1.2 技术栈

- 框架：Next.js 14 (Pages Router)
- 数据库：MongoDB (Mongoose) - 模型配置
- AI Proxy API - 渠道管理
- 位置：`projects/admin/src/pages/api/extend/`
  - 模型配置：`projects/admin/src/pages/api/extend/model/`
  - 渠道：`projects/admin/src/pages/api/extend/channel/`

## 2. 数据结构

### 2.1 模型配置（system_models 集合）

**Schema 文件**：`packages/service/core/ai/config/schema.ts`

```typescript
{
  model: { type: String, required: true, unique: true },  // 模型标识符
  metadata: { type: Object, required: true, default: {} }  // 模型配置
}
```

**metadata 中的模型类型**（ModelTypeEnum）：
- `llm` — 对话模型
- `embedding` — 向量嵌入模型
- `tts` — 语音合成模型
- `stt` — 语音识别模型
- `rerank` — 重排模型

### 2.2 模型渠道（AI Proxy API）

**数据结构**（ChannelInfoType）：
```typescript
{
  id: number;                          // 渠道 ID
  status: ChannelStatusEnum;           // 状态（0=未知, 1=启用, 2=禁用, 3=自动禁用）
  type: number;                        // 渠道类型 ID
  name: string;                        // 渠道名称
  key: string;                         // API Key
  base_url: string;                    // API 基础 URL
  models: string[];                    // 支持的模型列表
  model_mapping: Record<string, any>;  // 模型映射
  created_at: number;                  // 创建时间
  priority: number;                    // 优先级 (1-100)
}
```

## 3. API 设计

### 3.1 模型配置导出 API

```
POST /api/extend/model/exportModels
```

**请求参数**：
```typescript
{
  provider?: string;    // 模型提供商（可选，为空则导出所有）
  modelType?: string;   // 模型类型（可选，llm/embedding/tts/stt/rerank）
}
```

**响应**：JSON 文件下载（Content-Type: application/json）

**JSON 结构**：
```json
{
  "version": "1.0",
  "type": "models",
  "exportTime": "2026-05-21T10:00:00Z",
  "filters": {
    "provider": "openai",
    "modelType": "llm"
  },
  "models": [
    {
      "model": "gpt-4",
      "metadata": { ... }
    }
  ]
}
```

**核心逻辑**：
1. 验证请求参数
2. 构建查询条件：
   - 如果指定 provider，在 metadata 中按 provider 字段筛选
   - 如果指定 modelType，在 metadata 中按 type 字段筛选
3. 查询 `system_models` 集合
4. 组装 JSON 结构并返回文件流下载

### 3.2 模型配置导入 API

```
POST /api/extend/model/importModels
Content-Type: multipart/form-data
```

**请求参数**：
```typescript
{
  file: File;  // JSON 文件
}
```

**响应**：
```typescript
{
  success: boolean;
  data: {
    insertedCount: number;   // 新插入的模型数量
    updatedCount: number;    // 更新的模型数量
    failedCount: number;     // 失败的模型数量
  }
}
```

**核心逻辑**：
1. 解析 JSON 文件，验证格式和 version/type 字段
2. 遍历 models 数组
3. 对每个模型使用 `updateOne` 的 upsert 模式：
   - 如果存在相同 model 标识符，更新 metadata
   - 如果不存在，插入新文档
4. 返回导入结果统计

### 3.3 渠道导出 API

```
POST /api/extend/channel/exportChannels
```

**请求参数**：无

**响应**：JSON 文件下载（Content-Type: application/json）

**JSON 结构**：
```json
{
  "version": "1.0",
  "type": "channels",
  "exportTime": "2026-05-21T10:00:00Z",
  "channels": [
    {
      "name": "OpenAI",
      "type": 1,
      "base_url": "https://api.openai.com",
      "models": ["gpt-4", "gpt-3.5-turbo"],
      "model_mapping": {},
      "priority": 100
    }
  ]
}
```

**核心逻辑**：
1. 调用 AI Proxy API `GET /api/aiproxy/api/channels/all` 获取所有渠道
2. 过滤敏感信息（不导出 key）
3. 组装 JSON 结构并返回文件流下载

### 3.4 渠道导入 API

```
POST /api/extend/channel/importChannels
Content-Type: multipart/form-data
```

**请求参数**：
```typescript
{
  file: File;  // JSON 文件
}
```

**响应**：
```typescript
{
  success: boolean;
  data: {
    insertedCount: number;   // 新创建的渠道数量
    updatedCount: number;    // 更新的渠道数量
    failedCount: number;     // 失败的渠道数量
  }
}
```

**核心逻辑**：
1. 解析 JSON 文件，验证格式和 version/type 字段
2. 获取现有渠道列表（用于匹配）
3. 遍历 channels 数组
4. 对每个渠道：
   - 如果存在相同名称的渠道，调用 `PUT /api/aiproxy/api/channel/{id}` 更新
   - 如果不存在，调用 `POST /api/aiproxy/api/createChannel` 创建
5. 返回导入结果统计

## 6. 错误处理

| 错误类型 | HTTP 状态码 | 说明 |
|----------|------------|------|
| JSON 格式校验失败 | 400 | 文件格式不正确 |
| 参数无效 | 400 | provider 或 modelType 格式不合法 |
| AI Proxy API 调用失败 | 502 | 渠道操作失败 |
| 数据库写入失败 | 500 | 返回错误详情 |

## 7. 测试场景

### 7.1 模型配置导出测试

1. 按 provider 导出（如 openai）
2. 按 modelType 导出（如 llm）
3. 按 provider + modelType 导出
4. 导出全部（无筛选条件）

### 7.2 模型配置导入测试

1. 导入新模型（插入）
2. 导入已存在的模型（覆盖更新）
3. 导入格式错误的 JSON（应返回 400）

### 7.3 渠道导出测试

1. 导出所有渠道
2. 验证敏感信息（key）已过滤

### 7.4 渠道导入测试

1. 导入新渠道（创建）
2. 导入已存在的渠道（按名称匹配，覆盖更新）
3. 导入格式错误的 JSON（应返回 400）
