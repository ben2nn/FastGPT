# 知识库数据结构 Q-A-Index 模型需求

## 背景

在知识库（如法律法规等）导入和检索场景中，需要设计合理的数据分段结构，以提升搜索召回率和准确性。

## 核心结构

每条知识切片采用 **Q - A - Index** 三字段结构：

### Q 字段（检索问句）

用于向量检索匹配，内容应贴近用户可能的提问方式。包含以下内容：

- **知识标题**：该切片所属知识的标题
- **知识类型**：如"法律法规"、"行业标准"等分类标识
- **知识标签**：与该切片相关的关键词标签
- **模拟提问**：由 AI 针对 A 字段内容自动生成的若干虚拟问题，模拟用户真实提问场景

### A 字段（主体内容）

知识切片的核心答案内容。包含以下内容：

- **切片标题**：当前切片段落的标题
- **知识类型**：与 Q 字段保持一致，重复放置以增强上下文
- **切片正文**：切片的原文主体内容
- **原文链接**：切片内容的来源链接或引用地址

### Index 字段（辅助索引）

用于辅助检索，提升搜索质量。包含以下内容：

- **知识标签**：与 Q 字段中的标签内容相同，**重复放置**

## 设计要点

1. **标签双写**：标签在 Q 字段和 Index 字段中各放一份。经实测验证，两个字段都放标签的搜索效果最佳。
2. **Q 是 A 的摘要**：Q 字段整体可理解为 A 字段内容的结构化摘要，便于向量检索时快速匹配。
3. **AI 模拟提问**：Q 字段中应包含 AI 针对 A 字段内容自动生成的若干虚拟问题，使检索向量更贴近用户真实查询意图。
4. **A 中重复上下文**：A 字段中适当重复标题、类型等信息，确保切片内容自包含，不依赖外部上下文即可理解。
5. **Index 以标签为主**：Index 字段建议只放标签，保持精简，作为检索的辅助补充。

## 验证分析

### ✅ 正确的部分

**1. AI 模拟提问（HyDE 思路）—— 正确**

这是 RAG 领域经过验证的有效技术（Hypothetical Document Embeddings 变体）。用户提问通常是口语化、简短的（"数据安全法对企业有什么要求？"），而文档内容是正式书面语。模拟提问在语义空间中拉近了"用户真实查询"和"文档内容"的距离，对向量召回率提升明显。

**2. A 字段自包含 —— 正确**

RAG 检索后，LLM 只拿到切片内容来生成回答。A 中带上标题、类型、来源链接，保证了切片脱离上下文也能独立理解，这是最佳实践。

**3. 标签双写 —— 实测验证有效，原理可解释**

标签是关键词，向量检索擅长语义相似性但不擅长精确关键词匹配。标签同时放在 Q（向量检索）和 Index（关键词/BM25 检索）中，两种检索机制互补：Q 的向量召回语义相关内容，Index 的关键词检索补充精确命中。这很可能就是实测效果好的根本原因。

### ⚠️ 需要注意的问题

**1. Q 字段存在"语义稀释"风险**

Q 中混入标题 + 类型 + 标签 + 多个模拟提问时，embedding 模型会对整个文本生成一个向量，多个不同主题的信号会相互干扰，导致向量变成一个模糊的中间向量，和任何单一查询的匹配度都不是最优。

> **更聚焦的 Q 比更长的 Q 效果更好。**

**2. 成本和 Token 消耗**

三字段都重复标题/类型/标签，embedding 处理的 token 数会增加约 30-50%。知识库规模较大时（几万到几十万条），embedding API 调用成本和向量存储空间会相应增加。

### 📋 改进建议

| 维度 | 当前方案 | 建议调整 |
|------|---------|---------|
| AI 模拟提问 | 放在 Q 中和其他内容混合 | 考虑每条提问单独建记录，或 Q 中只放 **1-2 个**最核心的提问 |
| 标签双写 | Q + Index 各放一份 | 保留，但需确认 Index 走关键词检索机制（BM25 / 倒排索引），若 Index 也是向量检索则边际收益有限 |
| A 字段 | 自包含 | ✅ 保持不变，设计正确 |
| Q 字段结构 | 所有内容混在一个字符串 | 标题 + 类型 + 1-2 个提问为宜，控制 Q 的长度，避免语义稀释 |

## 优化后的示例结构

### 方案一：紧凑版（Q 字段精简，控制语义聚焦）

```
Q: "《数据安全法》第三章 数据安全义务 类型：法律法规 企业需要履行哪些数据安全义务？"

A: "《数据安全法》第三章 数据安全义务
类型：法律法规
标签：数据安全、合规、企业义务、数据分类分级
[切片正文内容...]
来源：https://example.com/data-security-law#chapter3"

Index: "数据安全, 合规, 企业义务, 数据分类分级"
```

### 方案二：提问拆分版（每条模拟提问独立建记录）

如果追求更高的召回精度，可将模拟提问拆成独立记录，A 和 Index 共享同一切片内容：

```
记录 1:
  Q: "企业需要履行哪些数据安全义务？"
  A: "《数据安全法》第三章 数据安全义务 | 类型：法律法规 | [切片正文...] | 来源：..."
  Index: "数据安全, 合规, 企业义务"

记录 2:
  Q: "数据安全法对数据处理者有哪些要求？"
  A: "《数据安全法》第三章 数据安全义务 | 类型：法律法规 | [切片正文...] | 来源：..."
  Index: "数据安全, 合规, 数据处理者"
```

> **注意**：方案二会增加记录数量，需权衡存储成本和召回精度。建议先用方案一验证效果，不满足再升级到方案二。

## 实现参考：法规类 CSV 转换脚本

以下分析基于 `scripts/convert_kb_csv.py` 的完整实现，为 Q-A-Index 模型提供了成熟的工程化方案。

### 切片拆分策略

法规类文档的拆分遵循以下规则：

| 层级 | 处理方式 | 说明 |
|------|---------|------|
| 文件头（文号、通知、落款） | 独立成块 | 单独一条知识，Q 为"XX法规是什么文件？由谁发布？" |
| 章节标题（第X章） | 不独立成块 | 作为上下文信息，附加到所属法条的 A 字段中 |
| 法条（第X条） | 基本拆分单元 | 同一条内的多款不拆分，保持完整性 |
| 引用合并 | 生成合并块 | 若第 N 条引用第 M 条，额外生成"第M条、第N条"合并语义块，原始单条保留 |

**法条边界识别**（`is_structural_line`）：

行首 `第X条` 是法条边界，但需排除断句延续的情况：
```
第十二条  应当依法办理...    → 新法条（条号后有空格）
第十二条所列情形             → 断句延续（条号后紧跟无空格短词）
第四条限制                   → 断句延续
第七条【安全保障权】         → 新法条（条号后跟标题标记）
```

**PDF 修复**（`clean_text`）：

自动合并被 PDF 解析错误拆开的行：
- 纯数字行（如 "30"）→ 拼回上一行
- 单位行（如 "万元"、"个工作日"）→ 拼回上一行
- 上一行未以句末标点结尾 → 当前行是上一句的延续，合并

### Q 字段生成策略

**AI 生成模式**：

通过 LLM 生成 1-2 句语义摘要，包含：法规名 + 条号 + 主题 + 核心要点。

Prompt 要点：
```
q：用于向量检索的摘要/索引文本。要求简短、准确，包含法规名、条号、主题和核心要点，1-2 句话。
```

**规则兜底模式**（dry-run / AI 不可用时）：

| 场景 | Q 模板 |
|------|--------|
| 普通法条 | "《XX法规》第X条规定了什么？" |
| 含义务/禁止的法条 | "《XX法规》第X条对[主题]有什么要求？" |
| 引用合并块 | "《XX法规》第X条、第Y条分别规定了什么？有什么关系？" |
| 文件头 | "《XX法规》是什么文件？由谁发布？什么时候施行？" |

### A 字段生成策略

采用**上下文头 + 原文**的格式，保证自包含：

```
【法规名 | 章节 | 条号】
[法条正文]
```

示例：
```
【中华人民共和国数据安全法 | 第三章 数据安全义务 | 第二十七条】
任何组织、个人收集数据，应当采取合法、正当的方式，不得窃取或者以其他非法方式获取数据。
```

上下文头的作用：
- LLM 回答时可直接引用法规名和条号
- 脱离检索上下文也能理解内容来源
- 不依赖其他切片的上下文

### Index 字段生成策略

**AI 生成模式**：

通过 LLM 生成 6-10 个口语化检索词，英文分号 `;` 分隔。

**规则兜底模式**：

```
法规名; 条号; 章节名; 关键词1; 关键词2; ...; 参见第X条
```

关键词提取来源：
1. 法规名称（必有）
2. 条号（必有）
3. 所属章节名
4. 正文中的政务术语匹配（如"注册资本"、"登记机关"、"高新技术企业"等）
5. 交叉引用（正文中提到的其他条号 → "参见第X条"）

### 批量处理优化

| 策略 | 说明 |
|------|------|
| 批量调用 | 每批 5-10 条法条合并为一次 LLM 请求，减少 API 调用次数 |
| 按序匹配 | 批量返回结果按数组顺序对应输入法条，避免标题匹配失败 |
| 回退机制 | 批量失败时自动回退到逐条生成；单条失败时跳过并记录日志 |
| Token 估算 | 每条约 800 token（q + indexes），上限 16K |

### 脚本使用方式

```bash
# AI 模式：完整生成 Q + A + Index
python3 scripts/convert_kb_csv.py \
    --input  "法规原始.csv" \
    --output "out-法规.csv" \
    --regulation "中华人民共和国数据安全法"

# Dry-run 模式：只拆分，不调用 AI（Q 为规则模板占位）
python3 scripts/convert_kb_csv.py \
    --input  "法规原始.csv" \
    --output "out-法规.csv" \
    --dry-run

# 快速验证：只处理前 5 条
python3 scripts/convert_kb_csv.py \
    --input  "法规原始.csv" \
    --output "out-法规.csv" \
    --limit 5
```

配置优先级：命令行参数 > 环境变量 > `scripts/config.yaml`
