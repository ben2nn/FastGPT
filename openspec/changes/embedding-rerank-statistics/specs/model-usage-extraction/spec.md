# Spec Delta

## Purpose

定义统计数据抽取的多模型拆分口径:知识库搜索节点的调用响应按参与模型拆分为独立的模型调用记录(向量、重排、搜索内问题优化 LLM、深度搜索 LLM),与既有对话模型记录同表存储、同口径统计,保证幂等与状态判定规则一致。

## ADDED Requirements

### Requirement: 知识库搜索节点拆行采集
数据抽取 SHALL 将知识库搜索节点的响应拆分为多行模型调用记录,并纳入统计:每次搜索执行产生一行向量记录(`model_category=embedding`,模型取响应中的向量模型名,tokens 取向量 tokens);实际启用重排时额外产生一行重排记录(`model_category=rerank`);响应含搜索内问题优化结果时产生一行 LLM 记录(`model_category=chat`);响应含深度搜索结果时产生一行 LLM 记录(`model_category=chat`)。所有拆分行的使用场景(`usage_scenario`)均为知识库搜索节点类型,应用、会话、时间戳等上下文字段与该节点响应所属消息一致。

#### Scenario: 常规搜索产生向量行
- **WHEN** 一次知识库搜索成功执行且未启用重排、未启用问题优化与深度搜索
- **THEN** 抽取结果恰好包含该搜索的一行向量记录,不产生重排、问题优化或深度搜索行

#### Scenario: 启用重排的搜索产生向量行加重排行
- **WHEN** 一次知识库搜索实际执行了重排
- **THEN** 抽取结果包含一行向量记录和一行重排记录,重排行的模型与 tokens 取自响应中的重排字段

#### Scenario: 搜索内问题优化与深度搜索行
- **WHEN** 一次知识库搜索的响应中包含搜索内问题优化结果和深度搜索结果
- **THEN** 抽取结果额外包含两行 `model_category=chat` 的 LLM 记录,模型与 tokens 分别取自问题优化结果与深度搜索结果,且不与独立问题优化节点的记录重复

#### Scenario: 原有对话模型采集不受影响
- **WHEN** 抽取包含 AI 对话、问题分类、内容提取、Agent、独立问题优化节点的消息
- **THEN** 这些节点仍按原口径各产生一行记录,`call_id` 与既有格式一致

### Requirement: 拆分行 call_id 唯一性与幂等
拆分产生的每行记录 SHALL 拥有全局唯一的 `call_id`:在同一节点响应的原始响应 ID 后追加模型子键构成(如 `:embedding`、`:rerank`、`:ext_llm`、`:deep_llm`);重复抽取同一时间范围时,已存在的记录不得重复写入。

#### Scenario: 同一搜索的拆分行 call_id 互不冲突
- **WHEN** 一次同时启用向量、重排、问题优化、深度搜索的搜索被抽取
- **THEN** 产生的各行记录 call_id 互不相同,且与任何其他搜索的记录 call_id 不冲突

#### Scenario: 重复抽取不产生重复数据
- **WHEN** 对同一时间范围先执行一次抽取,再完整重跑一次抽取
- **THEN** 向量、重排及 LLM 拆行记录的总数不变,无重复行

### Requirement: 拆分行调用状态判定
拆分行的调用状态 SHALL 遵循统一规则:响应含错误信息时判为 `error`;否则按各模型自身 tokens 判断,有 token 消耗判为 `success`,无 token 消耗判为 `error`;节点运行时间超过阈值且无任何输出时,相关行判为 `timeout`。

#### Scenario: 正常搜索的各行状态
- **WHEN** 一次启用了重排的搜索成功返回,向量与重排均有 token 消耗且无错误信息
- **THEN** 向量行与重排行的调用状态均为 `success`

#### Scenario: 无 token 消耗判为错误
- **WHEN** 某拆分行对应的模型 tokens 为 0 且响应无错误信息
- **THEN** 该行调用状态为 `error`

### Requirement: 拆分行积分与耗时记法
拆分行的积分(`total_points`)SHALL 记 0;节点级运行时间 SHALL 仅记在向量行,重排行与 LLM 拆行行的运行时间为空。

#### Scenario: 积分不重复计算
- **WHEN** 一次搜索被拆分为多行记录
- **THEN** 每行的积分均为 0,统计的积分合计不因拆行而放大

### Requirement: 模型归因取自调用时快照
拆分行的模型名 SHALL 取自调用响应中保存的模型名快照,抽取时不得依赖当前模型配置进行查找或换算;响应中缺失模型名的行按现行未知模型规则记为 `unknown`。

#### Scenario: 模型配置变更不影响已抽取数据
- **WHEN** 某向量模型在调用发生后从系统模型配置中删除,随后执行历史区间抽取
- **THEN** 该期间向量行的模型名仍为调用时快照值,不因当前配置而改变
